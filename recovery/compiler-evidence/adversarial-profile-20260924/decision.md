## Identity and search space

The pinned `CL.EXE` SHA-256 identities in `layout/toolchain.json` are MSC 5.00 `11e3c7d53b3efc085b7ad90c2190a1ddb395c8874f57aef3a5cfc0a4a0a0f504` and MSC 5.10 `cad40cef732beea3455225fbd62286c664166db7c3f87e2402e22b2e3f107771`. Their dependent passes are also pinned and rechecked by `tools/compiler.py`. The actual command uses `C:/tools/nmlgcdos/msdos.exe -e -v5.00 <pinned CL.EXE> /c <flags> UNIT.C`; `-v5.00` belongs to MS-DOS Player and does **not** select MSC 5.00. Full commands, stdout, untouched objects, object record hashes, SEGDEFs, publics, ordered fixups and exact source/context identities are in the local ignored `build/private/profile-study/{control,rect-adjust-flag,multiply,heldout,nibble-fixture}/` receipts. The exact sources and frozen plans are alongside this report. All newly compiled objects parsed; no parser or runner launch failure was reinterpreted as code generation.

The tested option bundles were `/AM /O /Gs` under both versions, MSC 5.10 `/AS /O /Gs`, `/AL /O /Gs`, `/AM /Ox /Gs`, and `/AM /Os /Gs`, plus MSC 5.00 `/AM /Os /Gs`. `/O`, `/Ox`, and `/Os` were separate explicit alternatives; the study did not infer all implied sub-options or undocumented defaults from their names. `/AS` changes default code pointers/calls to near; `/AL` changes default data pointers to far in these observed objects. Declarations in the frozen C sources still matter, so model effects on these sources cannot identify a global historical model. Earlier archived `/Od`, `/Or`, QuickC and additional source trials are evidence only for their recorded source/context combinations.

The ten-routine cohort was the two-function rectangle pair, `audioresource_get_dword`, signed-long absolute `nopsub_26552`, `rect_adjust_from_point`, `flagchar`, `multiply_and_scale`, `pad_id`, and held-out `shape3d_init_shape` and `file_get_shape2d`. The rectangle pair, audio dword, signed abs and shape initializer are exact controls. The unresolved selections have reviewed complete intervals; `file_get_shape2d` has a verified 95-byte target and far-pointer ABI. Shared `sin_fast`/`cos_fast`, multi-entry `font_set_unk`, runtime contributions, and uncertain code/data extents were excluded. Historical same-object membership remains unproved even for the compatible rectangle pair TU. The held-out plan and null predictions were frozen before its five compilations; a separate nibble fixture plan was frozen before its two compilations.

## Competing explanations and decision

| Explanation | Evidence that would favor it | Observed decision |
|---|---|---|
| A. Current family/profile adequate; source hypotheses differ | Exact diverse controls and version-insensitive source failures | **SUPPORTED as a viable explanation, not proved globally.** Two versions share multiple exact controls; failed source forms remain source/context combinations. |
| B. MSC 5.00 needed instead of 5.10 | Source-fixed target-specific improvements replicated in independent held-outs | **CONTRADICTED WITHIN TESTED SCOPE** as a version-only repair: rect-adjust, flagchar and multiplication do not improve. **COMPATIBLE BUT NOT IDENTIFIED** historically: 5.00 matches controls and differs on held-out pointer code. |
| C. Optimization/ABI options differ | An option fixes a target residue while preserving exact controls and full topology | **INCONCLUSIVE globally.** `/Os` failed the rect-adjust prediction; `/Ox` changed that function without repair; `/AS` and `/AL` fail the exact rectangle TU as written. Archived `/Os` version interaction preserves an alternative for another source/context. |
| D. Different original objects had different profiles | Repeated profile-specific signatures plus independently evidenced common object grouping | **INCONCLUSIVE / not yet actionable.** No proven original same-object component boundary or clustered multi-feature signature licenses per-object assignment. |
| E. TU/declaration context causes apparent profile effects | Frozen body changes under evidenced neighbor/declaration/order changes | **COMPATIBLE BUT NOT IDENTIFIED here.** Other Stunts TU-context probes demonstrate context effects; no historical TU grouping for this cohort is proven. |
| F. Assembly, runtime, shared entry or bad boundary | Independent provenance, CFG and whole contribution evidence | **Applicable to separately excluded populations; not an explanation assigned to the verified complete target intervals in this cohort.** |

The new fixture and held-out results expose real MSC 5.00/5.10 codegen differences, so the versions must not be treated as globally identical. Yet no alternative explains multiple previously unresolved historical features, no held-out unresolved prediction succeeded, and no per-object profile is supported. The strongest current conclusion is **compiler/profile uncertainty is real but not an actionable systemic blocker for the tested recovery lane**. Keep production at MSC 5.10 `/AM /O /Gs`; retain 5.00 and narrow options as research recipes with explicit source/TU scope. Do not change the baseline or assign arbitrary per-function flags.

New strict recovery: **0 functions, 0 bytes**. The exact 172-byte held-out result and exact 114-byte pair were already accepted under the production profile. Research objects were neither linked nor promoted.

**Single next discriminating experiment:** obtain one independently justified `file_get_shape2d` source/context candidate that reproduces the target's inline four-shift normalization and BX nibble mask without a helper or extra stack frame, then freeze that source and compile once under each pinned `/AM /O /Gs` version. Record whether the observed 5.00/5.10 immediate-width and local-home differences persist and whether either version explains the full 95-byte target while exact controls remain exact. The missing prerequisite is a target-close source/context; further flag sweeps on the current 114/138-byte forms have low identification value.

The 18 new compiler processes were 3 model/optimization controls, 6 rect-adjust/flagchar calibration, 2 multiplication calibration, 5 held-outs, and 2 language fixtures. All source-fixed version contrasts separated raw OMF metadata from effective code/fixup behavior. Detailed local receipts remain under ignored `build/private/profile-study/`; compiler binaries and generated OBJ files are not tracked.
