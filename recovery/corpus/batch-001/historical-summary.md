# Historical actual-recovery archive audit (batch 001)

Scope: historical `recovery/attempts/*/report.json`, `recovery/experiments/*/report.json`, and legacy `recovery/promotions/*.json` only when a real compiler object receipt, source identity, and function recipe link are present. Synthetic compiler fixtures and presentation-only proposals were excluded. The audit added **zero new batch compiler attempts** and performed **zero compilation**; it is a read-only archive triage. Rows refer to source, recipe, and report files instead of duplicating payloads. Missing evidence stays `null`.

- Coverage: **13 distinct real functions** (`audio_enable_flag2`, `audioresource_get_dword`, `copy_string`, `is_facing_camera`, `nopsub_26552`, `nopsub_326BA`, `nopsub_378AE`, `nopsub_378BC`, `parse_shape2d_helper`, `parse_shape2d_helper3`, `rect_compare_point`, `rect_is_inside`, `rect_is_overlapping`) and **43 archived compiler outcome records**: **14** durable grinder attempts, **22** supervisor/research experiment reports, and **7** legacy promotion receipts predating the current attempt archive. Legacy promotion records already represented by per-attempt reports were not duplicated. These are historical outcomes, not new batch trials.
- Functions with executable compiler outcomes: all **13**. Strict promotions: **10 rows** across audio_enable_flag2, audioresource_get_dword, copy_string, nopsub_26552, nopsub_378AE, nopsub_378BC, parse_shape2d_helper3, rect_compare_point, rect_is_inside, rect_is_overlapping. `parse_shape2d_helper` remains represented only by failed extent trials; `is_facing_camera` has research mismatches. A promoted output verifies compiler/build behavior, not a unique historical source.
- Repeated-output interpretation is split explicitly: **8 informative identical-output negative rows** where the archived source differs and the paired hypothesis states a predicted mechanism; **12 neutral or unresolved repeat rows** where a duplicate hash alone does not establish that mechanism. **13 other meaningful negative rows** remain. These are row-level archive counts, not independent samples.
- Category counts: BYTE_EXACT=1, BYTE_MISMATCH=8, EXTENT_MISMATCH=22, None=12. Extent and same-size byte mismatches dominate the negative evidence.
- Paired archived outcomes useful for retrospective worker training/evaluation include `copy_string`, `is_facing_camera`, `nopsub_326BA`, `parse_shape2d_helper3`, and `rect_compare_point`. In particular, `rect_compare_point` has three prior compiler outcomes plus its strict attempt report; `is_facing_camera` has 19 experiment reports plus one durable attempt, including correlated canary variants kept in one function cluster; and legacy promotion receipts add seven distinct previously omitted solved functions. These archives are retrospective only, not blind-run inputs.

## Evidence limits

Where available, reports retain original source and recipe identities, compiler object identity, emitted byte length, fixups/relocations, and bounded mismatch evidence. Legacy promotion-only records carry the promotion report, function card's recipe, source hash, object hash, byte count, and canonical full-build receipt. They have no recoverable per-attempt hypothesis, so those fields remain null. Some early failed attempts lack object receipts; their candidate code identity is retained only where the diagnostic records it. Model, reasoning, and token accounting remain null because these historical records do not record them.

No recovery report demonstrates usable DWARF or CodeView records embedded in the historical objects or recovered code. CodeView documentation/assets exist in the pinned toolchain tree, which establishes only debugger material availability in the distribution, not debug records in these particular builds. Actual debug-symbol availability is **unknown / not evidenced**.

`root_classification` records each card's tier/status/origin and leaves historical ASM authorship unresolved; `root_function_size_bytes` is the pristine function extent. A mismatch is observed output evidence. Source cause remains unknown unless explicitly linked to an exact compiler outcome; even a strict match does not prove a unique historical source.
