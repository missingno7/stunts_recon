# Bounded comparison against 98be001

The diagnostic feature set is frozen. This check supports a smaller interface and a tentative reduction in proposal overhead on selected cases. It does **not** establish better experiment choice or accepted recovery per unit of work.

## Design

Four real Stunts functions, three mismatches and one exact-contribution control. Eight fresh GPT-6 Astra / medium agent contexts received the same starting source, pinned compiler flags, strict status, history cutoff and evidence allowance within each pair. Only the initial text differed: X is the mismatch-island view from `98be0015e3354f54d7b045a136d783965d1eaaa5`; Y is the family-summary view. No synthetic controls are included here.

Initial context/source/presentation plus at most four additional file reads were allowed. Both conditions could read the same full instruction/alignment evidence and prior history. Full evidence omits the new aggregate `patterns` field, leaving decoded streams, anchors, alignment and islands. Agents could not inspect later repairs, the other presentation, this assessment or the broader repository, and could not compile or mutate files. Each proposed one experiment with observation, predicted machine change, falsifier and checked evidence, or abstained. The prompt was identical apart from case and presentation paths:

> Perform a bounded read-only experiment proposal in D:/prog/stunts_recon. Read ONLY recovery/evaluation/advice-comparison/CASE/context.json, source.c and CONDITION.txt initially. You may then read ONLY full.json and history.json in that same case directory, at most four additional file reads total (rereads count). Do not inspect other repository files, other presentations, internet, or later results. No compilation or file edits. All needed evidence is in the packet. Propose ONE next experiment or explicitly abstain if no justified permitted source experiment exists. State motivating observation; specific machine-level change predicted before compilation; result that would falsify explanation; existing hypotheses/evidence checked; additional filenames/read count. Respect blockers; may propose independent research rather than unauthorized source edits. Be concise but technically precise. Return your proposal only, no general diagnostic review.

`design.json` records source reports and packet hashes. `proposals.md` contains verbatim replies extracted from their completed run records. `usage.json` holds actual task duration and cumulative model usage. The recorded tool calls were inspected: all eight runs read only their assigned files, made no mutations or compilations, and respected the retrieval allowance. Packet hashes were rechecked after completion. The parent assessed the proposals after seeing both and already knew historical outcomes; assessment is not blinded. No source experiment was executed for this comparison.

Almost all the total-token saving comes from the rectangle's avoided reread; that run did not select the stronger source explanation. Pointer Y used slightly more tokens and took 14.0% longer. There is no consistent per-case speed advantage.

These are actual cumulative request totals, including repeated input context. Cached tokens are included in total input; output already includes its reasoning subset. They are not unique context lengths, prices or estimates from character counts. Wall time includes tool and service waits, concurrent execution and scheduling; the sum is not the elapsed duration of the overall project. Parent preparation/assessment work is excluded from these agent-only measurements. One sample per cell, no randomized repetitions, and only four selected functions preclude a robust causal timing claim. Large shared system/tool context and output truncation also influence retrieval costs. See the exact source fields and limitations in `usage.json`.

## Recovery and uncertainty

The evaluation made zero source compilations or promotions. Two earlier independent MSC 5.1 return-placement fixtures emitted identical 38-byte contributions, a negative result; neither was a new canary variant. No canary reopen was justified. Ordinary bounded recovery after this comparison is recorded separately in `recovery-followup.md`; its compiler attempts are not additional A/B samples. `nopsub_326BA` failed all three allowed hypotheses (34/52/34 bytes against 36; final object repeats the first). `copy_string` produced 40 bytes, then 56 differing bytes, then 56 exact bytes. Root freshly promoted it with whole-image equality in `recovery/attempts/copy_string/0004/report.json`. The decisive local-pointer and statement-order observations were available in the existing islands; no incremental recovery credit is assigned to the family summary.

The user's subsequent Luna/high preference and efficiency question led to a separate [two-packet model/configuration check](model-check.md). It does not alter the eight-run presentation comparison. Luna/high took longer and used more total tokens in those two proposal runs, with weaker proposals; its successful ordinary grinding run has no matched Astra baseline.

Presentation-size measurements against the same 98be001 baseline remain in `../near-match-families/results.json` and `routine-output-sizes.json`. Those test cases preserve the full evidence behind a smaller routine view. Better experiment choice and higher accepted recovery per unit of work remain unproven. Retain the frozen interface; do not add features based on this mixed result.

Current acceptance comes only from the completed fingerprinted `docs/current/validation.json`, not these archival comparisons.
