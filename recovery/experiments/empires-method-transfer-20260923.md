# Empires methods checked against Stunts, 2026-09-23

## Starting evidence and target structure

Empires did recover previously unknown original code, but `empires_reconstruction` did not start from an empty correspondence map. Its `docs/upstream-inventory.md` records a read-only import from `empires_forged`: 126 previously matching C entries, 20 matching ASM entries, 35 identified library entries, plus source, extent, profile, address-binding and receipt metadata. The local factory freshly rebuilt 125 C and all 20 ASM entries; one stale C receipt was refused. After its first new matching-C wave it already had 14,433 C bytes and 2,456 ASM bytes. Those were reconstructed sources, not original game source.

Empires' target has a 78,642-byte MZ load image, 106 ordered relocations, compact-model `_TEXT` starting at zero, and a frozen complete one-TLINK build. Stunts' MCGA load image is 200,000 bytes with 2,588 ordered relocations and medium-model far code. Its current exact image is a hybrid with 834 C bytes, 725 pinned runtime bytes and 198,441 raw initialized bytes; only seven original DGROUP data symbols and one code binding are reviewed in `layout/data-symbols.json` and `layout/code-symbols.json`. Empires' final `docs/current/status.json` has no raw EXE fallback, but its final and Stunts' current counts are not equivalent starting cohorts.

## Methods that transfer

Empires' useful mechanism was a sequence of **independent proofs**: known extent and tool profile, compiled full object with publics and complete fixups, module and data continuity probes, then a fresh natural whole-image link. `probe_module.py` and `probe_tu.py` exposed declaration, inline-ASM compiler path (`-B`), and relocation-order effects. `docs/current/tu-structure.md` shows how negative flag probes, alignment, private DATA and ordered FIXUPPs bounded translation-unit claims. Interface conflicts were tested against actual caller and callee objects before headers were unified. Genuine hand-written ASM and pinned runtime had their own owners; a C match was not forced for string/interrupt/register choreography.

Stunts already has the strict compiler/object diagnostics, bounded grinder, research batches, independent DOSBox-X compilation and whole-image validation. The main transferable step now is **frontier quality**: review actual procedure ownership and original symbol/frame facts before compiling a Restunts C hint. Broaden linker/data/TU support through real historical LINK differentials, as in `docs/current/data-binding.md`; do not copy Empires' compact-model binder or early selected-public-span adapters into medium-model Stunts.

## Boundary control demonstrated here

The new read-only `python tools/audit_function_extents.py` traverses direct 16-bit control flow from each named entry over the immutable MCGA image. It changes no inventory, eligibility, recipe or acceptance logic. It scanned 234 imported fully mapped intervals and surfaced four with non-NOP bytes unreachable from the named entry: `set_add_value`, `nopsub_3219D`, `preRender_patterned` and `vector_op_unk`. `preRender_patterned` has an out-of-interval jump, so its finding is particularly uncertain. Alternate entry points and embedded data remain possible in every case.

`vector_op_unk` is the actionable example. The importer marks `[0x23014,0x23072)` as one verified 94-byte interval. Pristine traversal reaches `retf` at `0x23068`; the following nine bytes at `0x23069` begin `push bp; mov bp,sp` and store AX to DS:4E92. Restunts `asmorig/seg012.asm:10111-10163` places those bytes before `vector_op_unk endp`, but its C function ends at the vector assignment. The 94-byte extent is therefore unsafe as a standalone C contribution until the tail's entry and ownership are reviewed. This is a mapping question, not a failed source attempt.

Next practical order: resolve the four interval findings; prepare reviewed complete CFG evidence for source-backed, no-relocation functions without such anomalies; then spend compiler attempts. Keep the harder far-call/data/CS families behind specific binding or representation evidence. A missing original DOS symbol map is not a reason to guess offsets from Restunts names.
