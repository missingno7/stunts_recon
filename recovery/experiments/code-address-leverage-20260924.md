# Far-code address capability, 2026-09-24

## Current proof and effect

Baseline `python tools/validate.py` passed 148 tests, independent compiler/binding parity for 18 active functions, and `HYBRID_EXACT`; queue was `CHEAP=0`, `MEDIUM=5`, `SUPERVISOR=592`. No source, manifest owner or recipe was changed in this experiment.

The fresh supervisor census found 346 distinct far-call load targets. Only two addresses had reviewed binding identities, leaving just three supervisor tasks with all far-call target addresses reviewed. `tools/derive_code_aliases.py` now reconstructs address candidates from the pinned pristine image, current verified mapped intervals, the original MZ relocation table and raw ownership. It requires a unique mapped target and at least two distinct verified caller functions whose exact five-byte `9A` CALLs have the corresponding relocated segment word and agree on the far frame and load address. It rejects ambiguous frame groups and records the exact target extent/hash and two full caller anchors. This produces binding **aliases**, never a claim about original PUBDEF names or TU membership.

The generator found 128 eligible raw aliases, including one already reviewed. It added 127 static entries to `layout/code-symbols.json`; the existing `code_symbols.py` resolver revalidated every added entry against current bytes, ownership, mapping and relocations after the write. A negative test removes an anchor relocation; another corrupts an extent hash. Both reject resolution. `recovery/code-alias-candidates.json` is the repeatable machine-readable derivation.

After `python tools/reconstruction_factory.py reclassify`, the registry covers 129 far-code addresses and **80 current supervisor tasks have every observed far-call target address reviewed**, up from three. Their candidate object FIXUPP modes, complete contributions, and historical TU contexts are separate obligations. No task was promoted or moved to MEDIUM merely because its target addresses are now known; the queue remained `592 SUPERVISOR / 5 MEDIUM` at reclassification.

## Actual archived OMF modes, not inferred from MZ

A bounded read-only inventory found 53 archived compiler OMF files across 14 current supervisor task IDs, representing 40 distinct object payloads. Their 78 candidate FIXUPP records comprise 45 `offset16` external target, target frame (methods 5/2); 26 `pointer32` of the same methods; one `base16` of the same methods; and six `offset16` with group frame/segment target (methods 1/0). This is candidate-object evidence, not a population estimate for the other supervisor tasks.

The six group/segment records all belong to `mmgr_get_chunk_size` trials under `recovery/corpus/endurance-001/mmgr_get_chunk_size/`. Those candidates emit 72 or 84 code bytes against a 38-byte oracle extent, so binding alone cannot make them exact. The lone `base16` record belongs to the `sub_35DE6` trial-002 object under `recovery/corpus/endurance-001/sub_35DE6/trials/002/`; it emits 60 bytes against 34. Implementing either binder mode now has at most a one-task observed candidate population and would not overcome the present source-shape mismatch. General binder support remains fail-closed; no LINK mode was added.

The current high-leverage next step is complete candidate-source/Object evidence for more of the 80 address-covered callers, followed by historical LINK differential fixtures for whichever unsupported OMF mode recurs in otherwise promising contributions. Do not treat MZ far calls as OMF `pointer32` proof. The bounded `mmgr_path_to_name` register-hint batch also yielded 44–54 bytes against 32 and did not justify a systemic compiler change; its frozen predictions and objects are under `build/private/research-batches/load_21228/7e8c80ea86ed/`.

The first post-alias `python tools/validate.py` passed 149 tests, independent exact code/binding checks for all 18 then-active functions, and `HYBRID_EXACT`. Reclassification retained `CHEAP=0`, `MEDIUM=5`, `SUPERVISOR=592` at that stage. Two later far-call wrappers were strictly promoted with the existing binder; see `recovery/experiments/far-wrapper-promotions-20260924.md` for the current acceptance result. `docs/current/status.json` reports raw initialized ownership and unknown classification bytes separately.
