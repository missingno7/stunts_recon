# Historical freeze gate and freshness contract

Run from the repository root in an authorized integrator session. This worker did not execute these commands: validate is reserved to the supervisor, and the commands below write under shared build/ paths outside F1.

## Gate commands

| Command | Gate/output and recorded expectation | Clean-state behavior |
|---|---|---|
| python tools/validate.py | Full strict validation: test discovery, pinned profile checks, fresh hybrid rebuild, independent DOSBox-X compile/assemble parity, oracle/image/relocation checks, and BSS/runtime placement. Active C/ASM contributions are compiled afresh. However its BSS real-link gate calls reallink and may use build/reallink/cache; empty that targeted cache for a fully fresh linker compile. |
| python tools/validate.py --image | Runs the complete validation above, then runs the additional real LINK 3.65 + EXEPACK diagnostic and writes build/validation/real-link.json. The image diagnostic is explicitly diagnostic-only; it does not replace the strict acceptance gate or prove the historical LINK response. | Same as validate. Both the BSS gate and appended image diagnostic may read persistent build/reallink/cache objects. Clear that directory first for a fully fresh real-link compile. |
| python tools/histbuild.py | Fresh pinned C/ASM historical-build experiment; writes a unique build/histbuild/<tag-timestamp>/ report and its own reallink subtree. It checks that no compiler/assembler objects were cached. Recorded current result has no raw-debt OMF objects, but reports the independent library-order relocation residual. | No clean build state required. The interactive runtime-capture path in CAPTURE.md is evidence collection, not a deterministic freeze gate. The port-header probes are compile-only and do not link or execute the game.

## Freshness and interpretation

For the strict gate, run validate.py; its production contribution build and DOSBox-X parity are fresh. For a fully fresh real-link compile inside validation, clear only build/reallink/cache first. validate.py --image adds a cached-capable diagnostic link unless that same cache is empty. histbuild.py is independently fresh by construction, but its library-order mismatch remains a separate historical attribution result.

The README’s current state and layout/manifest.json are the authority for raw ownership. Older acceptance sections labeled “Still open” or described raw rows during intermediate integrations; later integ33/34/40/42 records supersede those snapshots. Host-probe output status is not currently consistent across docs and must be rechecked before recording it as a freeze sub-result.
