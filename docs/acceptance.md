# Acceptance scope

The byte oracle is reconstructed from the four supplied assets using DSI, DIF and EXEPACK decoding. `layout/oracle.lock.json` fixes asset identities, header metadata, complete unpacked image, and the ordered MZ relocation table. The independently unpacked comparison is preserved in `evidence/unpack.json`. Verification never updates expected bytes.

The manifest partitions every initialized load-image byte into matching C CODE, matching C data, pinned runtime, or explicit raw ownership. A C CODE owner lists its complete `data_intervals`; each initialized interval also has one `MATCHING_C_DATA` partition owner tied to that CODE owner. `_BSS` contributions use a separate `bss_owners` partition of the verified startup clear range and contribute zero bytes, including any overlap with file-end zero fill. New C recipes must consume every nonempty SEGDEF as a full CODE or reviewed DGROUP contribution. Empty declarations, full public/external lists, all OMF fixups, and exact ordered relocations are checked. No secondary interval may overlap an unrelated accepted owner. An accepted data interval can be subsumed only with identical extent and bytes and an explicit `subsumed_data_owners` entry. Unknown OMF records, corrupt checksums, holes, overflow, and unsupported communal/BIG/32-bit storage fail closed. COMDEF communal allocation is explicitly deferred: neither its allocation order nor its storage ownership is inferred, and production rejects it. MSC B4/B6 local externals/publics are parsed with their scope intact: each local external resolves to a distinct public inside the object, cannot shadow a global binding, and each local CODE public must be a complete reviewed member of a group recipe. Diagnostic object inspection cannot grant acceptance.

The tested binders support no-fixup contributions, reviewed external DGROUP offsets, external far CALLs, the bounded mixed far-CALL/DGROUP mode, far code-pointer MOV offset/base pairs, paired CS-data offset/base MOVs with far CALLs, and the specific frame-callback object mode. Secondary DGROUP binding requires exact complete segment length and bound bytes, a raw or exactly subsumed owner, and at least one original CODE fixup whose target segment, group frame, bounded addend, and pristine operand independently place that whole contribution. Every data fixup is bound through reviewed code/data symbols or another complete secondary segment; unsupported shapes fail closed. Data-segment relocations are checked against the original ordered MZ table within their complete intervals. DOSBox-X independently recompiles and binds each secondary contribution. The symbol tables check original instruction bytes and relocation anchors. The function inventory supplies address and boundary provenance; source names are binding aliases, not claims about original PUBDEF names or original translation units.

A reviewed far-code alias requires an original `9A` far CALL or an original `MOV AX,offset; MOV DX,segment` pointer pair wholly inside an instruction-verified inventory caller. The segment word needs an MZ relocation, and the offset plus paragraph must land exactly at the independently mapped entry. Complete mapped targets require verified boundaries or emission bytes with start/end evidence, an unchanged original extent, and a complete raw, exact C, or pinned runtime owner. The single partial `sprite_make_wnd` entry is narrower: its exact first instructions, immediately preceding verified procedure end, pinned assembly label, raw ownership, and original relocated far CALL prove only the entry address; no complete function extent is claimed. For runtime ownership, the pinned OMF public must land exactly at the verified entry and the complete source member must bind. An anchor may lie inside the contribution being proposed because its bytes come from the immutable oracle, independently of candidate output. Every listed anchor is checked anew. Alias spelling must match the inventory name with the C underscore convention or be individually reviewed; it does not assert an original PUBDEF.

The mixed binder accepts one or more external far CALL fixups together with reviewed DGROUP offset fixups in a complete object. It binds every CALL from its reviewed code frame, every data offset from its reviewed DGROUP frame, checks each emitted fixup's shape and location, and preserves the source's exact ordered MZ relocation obligations. Additional CALLs do not relax the complete declaration, public, byte, or whole-image gates.

A DGROUP symbol's fixup addend must remain inside its independently grounded object extent. Reviewed field anchors may authorize their exact element offsets; a symbol without a grounded extent or field permits only addend zero. The resolver supplies these allowed addends to both the data-only and mixed binders. The sole reviewed folded-index exception is `_audiochunks_unk2` at DGROUP `0x86BC`: eight 76-byte records, bounded by original signed guards to indices 16..23. MSC folds `array[i-16]` into a signed `-1216` static addend (`-1214` for its second word). The pinned reference span, two hash-verified callers, exact guard, multiply, and indexed-access instructions, and the next object at `0x891C` are rechecked from the oracle. A recipe using such an addend must list each `folded_index_bindings` offset, field offset, and witness; the original instruction at that fixup site must be the reviewed guarded access. The complete object, fixups, relocations, and whole-image equality remain mandatory. In particular, an expression that reaches a separately labelled global through a large index into another symbol is rejected even if the resulting physical address happens to match the original bytes.

The CS-data mode is limited to the 60-byte `sprite1`/`sprite2` island in seg012. The pinned reference's 60 byte declarations, pristine island hash, a relocated original CS segment word, and separate original offset instructions ground its two 30-byte symbols. Each candidate reference must be a zero-addend adjacent MOV AX offset / MOV DX segment pair; both OMF fixups and the base-word MZ relocation are mandatory. Calls in the same object remain separately grounded far-code aliases. This mode does not grant access to neighbouring code or data.

Compact DGROUP entries record a binding name, original load address, and storage class. At resolution time, the resolver checks the locked image and DGROUP frame, then decodes an unrelocated 16-bit memory displacement equal to that address inside a hash-verified, instruction-verified procedure. A displacement plus an unrelated immediate is not an address anchor. Names remain aliases: a reference-source label or candidate spelling does not prove the original C declaration, PUBDEF, or TU. Reviewed widths cite a specific span from one label to the next in the pinned reference `dseg.asm`; that span is a reference hypothesis, not an original-object fact. The `_state` aggregate has a separately reviewed 1,120-byte label span at DGROUP `0x8D24`, ending at the next label `0x9184`; resolution checks the pinned reference identity, recounts the span, calibrates its coordinates against `_gameconfig`, and rejects overlap with another reviewed-width object. Exact reviewed field anchors can separately authorize a field offset. Access width alone never grants an object extent.

The 256 indexed `_g_ascii_props` bytes have a separate pinned declaration and oracle-byte proof; the following byte is checked as padding and grants no index 256. `_audiodriverstring` is a five-byte reference span. `smouspriteptr`, `mmouspriteptr`, and `mouseunkspriteptr` are each one four-byte `dd` declaration in the pinned reference, so their second words are bounded fields of the same pointer instead of separate global allocations.

`tools/data_extent_generator.py` scans the locked image and instruction-verified function inventory for a constant scale of an index loaded from the same memory location tested by two dominating bounds. Both bad branches must bypass the indexed access. It normalizes field displacements within a stride, unions bounded witnesses, and rejects storage-boundary crossings, incompatible scales, interior independently anchored symbols, and unbounded indexed displacements within the proposed span. A compact `generated_extent` records the source base, stride, inclusive index bound, field offsets, and access sites; the resolver reruns the scan against the oracle before granting addends. This is separate from reviewed reference-span widths and does not infer a bound from a check performed after an access. The current generated scan corroborates the reviewed `_audiochunks_unk2` slice (eight 76-byte records). The `audio_carstate` access based at DS:`0x97DC` has a 40-record wrap check after the access, without a dominating entry bound; it receives no generated extent.

A multi-function recipe names a group and lists every contiguous inventory member with its exact original extent, hash, and emitted public offset. This includes every MSC local CODE public, whose independently reviewed extent is recorded as a local member. One complete object replaces exactly that interval; internal self-relative near CALL fixups use the emitted target public and computed signed displacement, while external fixups use the existing strict binders. A group may subsume an accepted single-function owner only when the recipe lists that owner, its extent equals a group member, and its active source is freshly recompiled to the original bytes. Otherwise the group may replace only raw ownership. Full object declarations, ordered fixups and relocations, and fresh whole-image equality remain required.

Runtime members are matched by pinned archive/member identities and complete extents. Fixup-bearing owners carry the complete ordered FIXUPP list, full segment/public/external declarations, exact original MZ relocations, and a `runtime-member-v1` binding. Near transfers resolve to exact publics of already accepted pinned runtime owners; far CALL/JMP pointers use the original relocated `_TEXT` frame and accept the narrow OMF source-segment frame-method-0 form. DATA offsets use independently anchored DGROUP aliases with bounded addends. Segment-local targets use the full declared segment and checked displacement. Unsupported fixup shapes fail closed. Some complete secondary DATA remains explicitly raw-owned: each such interval has a grounded placement, all of its bytes and fixups are verified on every build, and later source promotions cannot consume it silently. BSS needs an independently verified range and a complete declared extent.

Default overlapping LEDATA remains rejected. Specific owners carry a reviewed `pinned-ordered-ledata-v1` policy with exact record offsets, payload hashes and overlap sites. Overlapping writes covering a fixup must agree byte-for-byte with each other and the merged field. Bounded LIDATA16 is expanded and checked in full; a FIXUPP over iterated data remains unsupported. The two known CRT absolute marker publics are accepted only at their exact sentinel value and do not bind code or data. Untouched historical LINK fixtures test ordered LEDATA policies with both pinned compiler distributions. No global checksum or overlap exception exists.

Literal C includes are resolved before compilation: angle headers come only from the hash-pinned profile INCLUDE directory, and quoted headers come only from tracked `include/` files. Search records each included path and SHA-256 in its frozen environment; recipes freeze the same closure, and strict acceptance and DOSBox-X independently verify it. The historical `#pragma pack(1)`, `pack(2)`, `pack(4)`, and `pack()` forms pass through unchanged and are recorded with their source location and value in that closure. No other pragma is allowed. Sources without includes or pack directives have an empty closure.

The compiler profile is a compatibility hypothesis: Microsoft C 5.10 medium model with `/O /Gs` is pinned, but matching code under 5.00 prevents a unique historical version claim. Original TU grouping, general linking, arbitrary segment/frame modes, QuickC BAKPAT, local communal records, and CS-relative storage outside the reviewed sprite island remain technical work. Search can inspect unsupported objects and context hypotheses without weakening production.

Promotion preserves all existing owner intervals except the explicitly listed, freshly reverified owners subsumed by a multi-function contribution. A new single function or complete pinned runtime member can replace only a wholly raw interval. Runtime publication uses `promote_runtime.py` and the same exclusive lock, staged whole-image build, journal, input snapshot, canonical whole-image build, and rollback path as C promotion. Replacing an accepted function requires the same interval and fresh exact output. Canonical input identities are checked before and throughout serialized publication. Scratch histories are outside acceptance inputs.

Full validation combines negative technical tests, fresh pinned C compilation, runtime binding, complete hybrid image and ordered relocation equality, and independent DOSBox-X recompilation. Reports are derived under `build/validation/` and `build/exact/`. Source hashes, object bytes, and every binding are checked anew; historical receipts cannot authorize acceptance.
