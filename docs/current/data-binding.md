# Original DGROUP and bounded linker support

`binder.py` supports complete single-public code contributions containing external offset16 FIXUPP records with target frame method 5, external target method 2, zero target displacement, and a proven DGROUP symbol. It checks the complete ordered fixup list, original indices, encoded addends, all segment/group/public/external declarations, full code length, and absence of other initialized/BSS contributions. The linked value is `target load address - DGROUP frame address + encoded addend`. Compiler objects stay unchanged. No desired opcode/operand bytes enter that computation; the completed contribution is then compared to the immutable oracle.

No load relocation is generated by these offset16 references. Both recipe and original extent must have no MZ relocation, including a relocation crossing the extent boundary. Far pointers/calls, other frames, self-relative references, nonzero target displacement and overflow still fail closed. This is not a general medium-model linker or proof of original translation-unit boundaries.

## Independent historical linker check

`tools/linker_probe.py` compiles ordinary C and passes the untouched object plus a synthetic data-provider test object to the pinned historical LINK with `/NOD /MAP`. The provider is test scaffolding, never production ownership. LINK's map independently supplies the group origin and public address. Twelve differential fixtures cover MSC5.00 and MSC5.10, word/paragraph data alignment, and encoded addends 0, 3 and 127; each complete linked code contribution equals the binder result and has no MZ relocation. Word alignment deliberately puts `_DATA` at byte 14 inside paragraph zero; paragraph alignment moves DGROUP to paragraph one. This catches using a segment start or caller's code frame as the data frame. Receipts: `recovery/dgroup-linker-proof.json`. Unit tests rerun four of these differential cases plus rejection tests.

## Original address evidence

Pristine image `0x1CC6C` contains `BF 77 2B` (`mov di,2B77h`). Its immediate at `0x1CC6D` has original relocation pair `1000:CC6D`. Startup then executes `mov ss,di` at `0x1CC7F` and `push ss; pop ds` at `0x1CCD8`. Therefore DGROUP's load-image coordinate is `0x2B770`. Pristine startup at `0x1CCCC` initializes DI=`55CAh`, CX=`AD20h`, subtracts DI from CX and clears that byte range. Thus DS:[55CA,AD20) is BSS, including the two arrays below. Machine anchors and the actual relocation are checked on every bound production probe through `layout/data-symbols.json`.

| External | DS offset | Load coordinate | Storage | Instruction evidence |

| `_audioflag2` | 4EC1 | 30631 | Initialized byte | image273B2, setter address at +2 |

Coordinates in this table are hexadecimal. BSS addresses beyond the 200000-byte stored image are logical addresses, not file offsets or new initialized-byte ownership. Array lengths and index signedness are not proven. C uses external arrays of unspecified length and ordinary integer indices; the emitted complete function matches. The zero-extension proves unsigned byte values but does not uniquely identify the original return declaration.

Restunts commit `5c38f258f482e7d28f1ccce73da8992dccbbee89` supplies names and semantics: `game.asm:56878` and `:56928` for startup, `asmorig/seg027.asm:442`, `:1150`, `:1163` for these routines, `asmorig/dseg.asm:20671`, `:35575`, `:36139` for declarations. Its materialized BSS zeros are not an oracle. The original instructions and relocated startup establish the addresses independently.
