## State at handoff

- **Build:** 38 historical C units compiled unchanged under `PORT_BUILD` + 23 host objects; links. Generated link stubs: **29 functions, 2 data symbols** (was 117 + 4 at M0). Inventory: `build/sdl3/stub-inventory.json` (regenerated by the build).
- **Pixel-exact vs the original game (Port Forge indexed framebuffer + palette):** splash, title, main menu — 0 differing pixels, 0 palette bytes. Regression fixtures in `tests/fixtures/sdl3/` (refresh via `tools/porting/pack_sdl3_reference.py`).
- **Timing:** host timer at 99.998 Hz matches the Port Forge measurement; VGA status register (3DAh) modelled on a virtual 70.086 Hz clock.
- **Determinism (test-only):** `tests/fixtures/sdl3/startup-seed.json` seeds the startup state captured from Port Forge v7 (status reads, timer counter, CRT and Kevin PRNG state). Seeded runs select the same copy-protection word ("previewing") as the original. The protection helper reads the expected answer from game memory and types it through normal input; the protection check itself is untouched. Default gameplay uses real randomness.
- **Routine differential harness:** `tools/porting/diffharness/` runs the original machine code (Unicorn, relocated locked image) against the port C routine and compares declared registers/memory. Passing cases: `sprite_1_unk3`, `draw_filled_rect`, `mulscl`; a negative case detects injected mismatches. The port test DLL currently builds only the units those examples need.

## Where it stops

A seeded scripted run passes protection, enters `run_game` and records simulation step 1 (`game_frame=1`), then faults before the first race frame is rendered: the polygon record at `polyinfo+174` has point count byte `0xDD` read as -35 (record pointer `0x8a0029`). Port Forge continues past frame 1. Most likely a 3D-renderer/polygon-list translation or memory-model issue on the race-render path (candidates: `preRender_*`, polygon insertion/list building, shape3d transform); not yet isolated.

## Known gaps

- `validate.py` exits nonzero in port worktrees when optional inputs are missing: 3 SDL framebuffer tests skip without `build/sdl3/m1b-*` captures, and asset-parser tests skip without a local `assets/` directory. Provide those inputs (or make the tests generate/skip cleanly) before relying on the gate here.
- Diffharness DLL does not yet build all of `port/*.c` (unresolved application/runtime dependencies).
- Race frame, driving, replay determinism, audio (silent `pc15` adapter), and the remaining 29 stubs are not done.

## Recommended next steps

1. Extend the diffharness DLL to all port units, then write differential tests for every race-path routine (3D renderer, polygon/line, `preRender_*`, `skybox_op_helper`, shape transforms); fix mismatches — this should locate the `polyinfo` fault without in-game iteration.
2. Parallelise remaining stubs by family, each with differential tests, in separate worktrees/branches; integrate serially.
3. Reach the first race frame; compare framebuffer + palette + GAMESTATE/CARSTATE + first-N-step trace against Port Forge with the seeded startup; add regression tests.
4. Then driving input and replay playback determinism (20 Hz simulation with catch-up on the 99.998 Hz tick), then audio.

Working rules that proved necessary: one writer per branch, time-boxed workers that commit early, and routine-level differential tests instead of whole-game iteration.
