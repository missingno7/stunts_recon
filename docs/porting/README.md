# Porting documentation

This index connects the original executable's platform boundaries to resource formats, deterministic state, and observed runtime behavior. It documents compatibility contracts and evidence; it does not implement replacement services.

## Types and pointer model

`include/stunts_types.h` names the original 8-, 16-, and 32-bit integer spellings with macros (`I8`, `U8`, `I8S`, `I16`, `U16`, `I16S`, `U16S`, `I32`, and `U32`). `I16`/`U16` expand to the original 16-bit `int`/`unsigned int`; `I16S`/`U16S` preserve source declarations spelled `short`. The original medium model uses far code and near data, with segmented `FAR`, `NEAR`, and `HUGE` pointer qualifiers. A host port can redefine the listed macros before including the header to use its fixed-width integers and flat pointers. The header uses macros instead of typedefs because typedef substitutions changed OMF `EXTDEF`/`COMDEF` ordering in the Q2, Q3, and Q4 probes.

Keep one-line `/* PORT: ... */` comments beside code whose behavior depends on the original ABI or machine, such as 16-bit integer wraparound, segment:offset arithmetic, far-pointer normalization, structure packing, signed shifts, or plain-char signedness. Find subsystem annotations and portability hazards with `git grep -n -E 'PLATFORM\([^)]*\)|PORT:' -- src`; PowerShell also supports `Get-ChildItem src -Filter *.c | Select-String -Pattern 'PLATFORM\([^)]*\)|PORT:'`.

## Remaining unknowns and evidence needed

| Unknown | Current limit | Best next evidence |
|---|---|---|
| Effective PIT channel-0 mode/rate, INT 8 chaining and timer callback counts | The game writes `0xB6` to channel 2, then loads channel-0 divisor 11,932; the inherited channel-0 control state remains unknown. Old harness counts are approximate, not an in-game trace. | Run the [interactive DOSBox-X capture](CAPTURE.md) at title, live-race and replay states. Save `LOGCPU.TXT` and before/live/after `INTVEC` snapshots; analyze them with `tools/porting/analyze_capture.py`. Use a separately calibrated interval before reporting rates. |
| Actual simulation, render, catch-up and replay-step counts | Port Forge measured a 20 Hz target in the sampled race and 0–13 frame-counter advances between consecutive rendered publications; replay mode pairs show 0/1/2. The 10 Hz target was not reached, and the trace does not add independent simulation-step IDs. | Keep the sampled mode-scoped histograms and counter-reset caveat in the [runtime oracle](runtime-oracle.md); capture a workload that selects 10 Hz before generalizing. |
| VGA retrace and palette traffic | Startup palette upload uses BIOS INT 10h; `random_wait()` polls status bit 3 during setup. Port Forge sampled `FrameStart` only; `VerticalRetraceStart` and guest DAC/status I/O counts remain unmeasured. | Capture a workload with retrace-phase observation or guest I/O tracing across startup and rendered frames; separately account for BIOS video calls. |
| Audio mode and callback cadence | Port Forge counted nonempty guest audio render batches, not `.DRV` hook invocations or host callbacks. AD15 selection, device port traffic, and callee cleanup remain unmeasured. | Preserve the distinct event types in the [runtime trace schema](runtime-oracle.md); use a matching driver/runtime observation before assigning device behavior. |
| Replay-control bits 6-7 and byte-to-glyph names | The player path consumes bits 0-5. All 10,646 supplied `DEFAULT.RPL` frame bytes have bits 6/7 clear; the `stunts_forged` copy is hash-identical, so upper-bit behavior has no sample coverage. Font bytes index glyphs directly, but their character encoding is not established. | Inspect an independently sourced replay containing bits 6/7 and obtain the original font/editor byte-name mapping. Preserve all replay bits and legacy text bytes; do not assume CP437 or Unicode. |
| HIG byte `0x10`, `.CKM`/`.TD` grammar, and VCE record tails | HIG byte `0x10` varies across records, is skipped by the renderer, and is not initialized on insertion. No `.CKM`/`.TD` sample or reader path was found. VCE drivers read selected tail offsets, while meanings of other bytes remain unknown. | Preserve HIG byte `0x10` and every complete VCE record. Keep `.CKM`/`.TD` opaque unless a matching sample and reader are found. |
| Build-time track-table pairing in `build_obj` | `obj_seg004` reads `td15p_9` with reversed offsets and `td14tb` forward, while setup and other consumers imply the opposite table roles. This is an unresolved declaration/context question. | Reconcile the accepted symbol bindings and original object context at `build_obj` before changing map semantics; keep file-row orientation separate from world-coordinate lookup. |
| Unclassified state roles and physical units | Three replay-role meanings were clarified; several remain unknown, including seven replay-role globals and the `g_corkscrew_type_flag` consumer. Of 341 unit-unknown registered globals, 84 are assigned/shared with simulation (63 exclusively). | Prioritize accepted access/call-flow evidence for core car state, SIMD coefficients, `opponent_spd_tbl`, and dynamic terrain height. Measure concrete conversion/equation sites only when an independent state trace is available. |
| Fallback formats and declared extents | Supplied assets produce 212 catalogued files, including 189 extension-specific or opaque-handler entries and 23 inventory-only. `.VCE` declared-size semantics and some fallback formats such as `.XVS` remain open. | Inspect an actual sample with its accepted reader, or acquire a matching original asset; validate complete extents and byte-identical round trips before adding schema claims. |

## First-port implementation tasks

These are implementation items rather than unknown historical facts:

- Provide host file, resource and audio dispatch hooks.
- Resolve stored segment:offset values through a bounded host address-space adapter; retain each segment, offset and complete object extent explicitly.
- Add port-only TU views/adapters for the three remaining strict-central compiler conflicts (`call_read_line`, `read_file_with_retry`, and `send_audio_stop_event`); preserve the original record-order-sensitive spellings and machine contracts.
- Implement the SDL3 timer, input, audio and indexed-renderer seams from the frozen behavior and state contracts.
- Emit the [shared runtime trace schema](runtime-oracle.md) from the SDL3 adapter, keeping simulation steps, guest audio publications and host callbacks as separate events.

## Evidence and tools

- [Platform boundary inventory](platform-boundary.md) and [structured boundary data](platform-boundary.json) map DOS/BIOS, input, timer, audio, memory and video-service call sites.
- [ASM migration inventory](asm-migration.md) and [structured inventory](asm-migration.json) list each ASM owner, public routine, pinned runtime member, port category, replacement direction, and first-link requirement. Its completeness test compares rows against `layout/manifest.json`.
- [State model](state-model.md) is the curated replay/layout guide. Run `python tools/porting/state_model.py` to regenerate the full symbol and per-translation-unit type inventories under ignored `build/porting/state-model.{md,json}`. Compiler sizes and nested aggregate offsets use isolated canonical-profile probes; `--no-probes` reuses the complete current caches `build/porting/typeprobe-reports.json` and `build/porting/member-offset-results.json`.
- [Runtime measurements](runtime-measurements.md) separates measured observations from source-derived timing; [interactive capture instructions](CAPTURE.md) cover debugger traces and vector snapshots. Reproduce the no-input DOSBox-X run with `tools/porting/run_runtime_probe.ps1`; the script uses original local `assets/` and the local DOSBox-X executable and writes only under `build/porting/runtime-probe/`.
- [Port Forge runtime oracle](runtime-oracle.md) records the v7 timer, game-frame, pause, render and audio observations, trace fields, SDL3 producer contract and coverage limits. Normalize an event trace with `python tools/porting/normalize_portforge_trace.py TRACE.jsonl --out build/porting/normalized.jsonl`.
- Run `python tools/porting/format_reference.py assets --report build/porting/asset-validation.json` and `python tools/porting/audio_bank.py --verify-all --json build/porting/audio-bank-validation.json` to regenerate format and audio-bank reports. Both readers are read-only with respect to `assets/`.
- [Host compiler probe](host-probe.md) records the GCC 12.2 MinGW hazard survey. The [port-only declaration headers](port-headers.md) and `host_probe.py --mode compat` / `--mode strict-central` compare per-TU compatibility views with central declarations; all overlays and objects stay under ignored `build/porting/host-probe/`. This is an SDL3 preparation aid, not a matching-build profile.
- Other guides: [audio drivers and banks](audio-drivers.md), [runtime execution model](runtime-model.md), [modes and built-in editor](modes-and-editor.md), and [asset formats](formats.md).
